# mdui repository guide

## Answering

Reply in English regardless of the user's language except when they explicitly
write "пиши на русском!!!" or "отвечай на русском!!!". In any other case write
your responses in English.

This repository is MD UI: the repository every App of MD App is forked from.
An agent tailoring a fork reads [`APP-CREATOR-AGENT.md`](APP-CREATOR-AGENT.md)
instead of this file; this one governs work on MD UI itself.
Product language, requirements, PRDs, ADRs, and Provider profiles live in
`agentshouse/mdruntime` (`CONTEXT.md`, `docs/requirements/ledger.md`,
`docs/prd/`, `docs/adr/`, `docs/providers/`). This repository holds no
glossary or ledger of its own, and shaping happens there. Do not invent
product behavior, names, or architecture during implementation.

## Product invariants

- **Strict replacement.** Every review and merge boundary has one current
  implementation.
  Delete obsolete schemas, payload forms, aliases, compatibility readers,
  deprecated APIs, transitional branches, duplicate implementations, defensive
  branches without a demonstrated case, and dead code. Pre-MVP behavior and data
  are not preserved.
- **No speculative fallback.** A fallback is admissible only for a demonstrated
  infrastructure reason. A fallback that changes domain behavior needs explicit
  User approval recorded at its single canonical owner.
- **Nothing here is privileged.** Every screen and component goes through the
  public MD Runtime API. An App Creator's fork may change anything in this
  repository, so no part depends on being unchanged.

## Find the authority you need

Start with the task or ticket and `README.md`. Use [`docs/README.md`](docs/README.md)
to reach the owner for the concern. Follow only relevant links. If two current
owners conflict, follow [`docs/agents/ARTIFACT-AUTHORING.md`](docs/agents/ARTIFACT-AUTHORING.md)
instead of choosing one silently.

When documents disagree, use `agentshouse/mdruntime` `CONTEXT.md`, then the
current decision owner there. The roadmap settles order, not behavior. An
unanswered design question returns to that repository's requirements ledger §2
instead of being invented during implementation.

## Documentation ownership

- `docs/` contains development knowledge.
- One fact has one owner. Link to it instead of restating it. See
  `docs/agents/ARTIFACT-AUTHORING.md`.
- `docs/backlog/archive.json` is generated by repository tooling and is not
  hand-edited.

## Engineering conventions

- Comments in code are not allowed. Names and types carry the meaning; "why"
  belongs in git history, ADRs, and `docs/`. The one exception: every interval,
  whether a poll, a cadence, a timer or a retry period, states its reason in a
  one-line comment directly above its setting.
- Tests protect observable behavior, not implementation. Read
  [`docs/agents/TESTING.md`](docs/agents/TESTING.md) before changing behavior
  or tests.
- A folder is a namespace: do not repeat its name in a file name.
- Tooling lives in `scripts/` and is reachable through `npm run ops`. Derived
  artifacts live in gitignored `tmp/`, except the built App in `app/`, which
  the Provider builds from the committed tree and which is committed for that
  reason alone.
- Temporary command inputs such as PR bodies and review briefs live under the
  owning worktree's `tmp/`, never a generic host-wide `/tmp` path.
- The App is plain HTML and TypeScript ES modules in `src/`, without a
  framework. Relative module imports use `.js` specifiers. `app/` is the
  built App the Provider builds and serves, committed and written by
  `npm run ops -- build`; change `src/`, rebuild, and commit both.
  TypeScript checks types, swc compiles, Vitest runs pure and static specs,
  oxfmt formats, and dependency-cruiser enforces neutrality. Playwright runs
  browser specs in Chromium over the published MD Runtime's in-memory Adapter.
- Node, npm, and dependency versions are pinned in `package.json` and
  `package-lock.json`. Keep the Node and npm pins aligned with Agents House.
- Dependencies stay minimal: the MD Runtime, the Adapter, and what they pin.
  For the Markdown renderer only, the User approved `micromark@4.0.2`,
  `micromark-extension-gfm@3.0.0`, and their locked dependencies; retain the
  pinned profile and browser safety acceptance. See the
  [approval receipt](docs/agents/renderer-dependency-approval.json).
  An App Creator's agent adds whatever its fork needs later.

## Ticket delivery

One agent owns one Assignment: one branch, one dedicated worktree, one PR, and
one review sequence. Manual launches and the Master (`docs/agents/MASTER.md`)
use the same interface.

1. Product-code tickets use `/h-implement`. Smaller tooling, documentation,
   diagnosis, and mechanical tasks use their narrower workflow.
2. The PR is ready when its review sequence is complete with no open `defect`.
   `npm run ops -- merge <number>` squash-merges; the implementer never runs it.
3. For every test decision, follow `docs/agents/TESTING.md`. The implementer
   runs those tests. Merge does not.

This repository publishes no package. There is no release step after a merge,
and no merge here ever owes one.

## Commands and infrastructure

`npm run ops -- <area> <command> [args...]` is the operator interface. Run
`npm run ops` for its current command list.

For the full Linux gate, formatting, individual lanes, and spec slices, use
the [runner commands in TESTING.md](docs/agents/TESTING.md#runner). Every
check runs in that Compose service.

## Skills and tracker

- `.agents/skills/**` and `scripts/house-baseline.mjs` are vendored from
  `agentshouse/house`; skill files carry a provenance header. The `base` tier
  holds what every repository in the house shares; the `md` tier holds what
  this repository shares with its two siblings. Never edit a vendored file
  here: `npm run ops -- house check` runs in the check lane and refuses the
  drift by path, expected hash and actual hash. Route the change to `house`,
  then run `npm run ops -- house sync`.
- `.claude/skills` is the Claude Code view of the same project skill directory;
  `.agents/skills` remains the source of truth.
- Shaping, `/grill-with-docs -> /h-to-spec -> /h-to-tickets`, runs in
  `agentshouse/mdruntime`, which owns the PRDs this repository implements.
  Tickets for this repository are published here and audited with
  `/h-audit tickets`.
- `/h-implement` is claim, `/h-tdd`, `/h-code-review`, and residuals. Use it
  only for real product-code work.
- `docs/agents/issue-tracker.md` is the sole owner of local-ticket state,
  format, dependency semantics, publication, and the GitHub Issue boundary.
- Domain docs use `agentshouse/mdruntime` `CONTEXT.md` and the decision owners
  routed by `docs/agents/ARTIFACT-AUTHORING.md`. See `docs/agents/domain.md`.
